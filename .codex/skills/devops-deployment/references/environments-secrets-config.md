# Environments, Secrets and Configuration

Treat configuration as an interface with validation, ownership and environment scope. Define required variable names/types without committing secret values. Keep development, preview, staging and production identities separate for databases, payment modes, domains, OAuth callbacks, queues and destructive integrations. Browser-exposed prefixes such as `NEXT_PUBLIC_` must never carry secrets. Prefer short-lived credentials and OIDC/workload identity where supported, while keeping deployment credentials scoped to deployment only. Validate required config at startup/build boundaries and fail with non-secret diagnostics. Rotate credentials with overlap when possible and document ownership/expiry. Preview environments should use isolated or explicitly read-only production dependencies. Audit logs and CI output must redact tokens, cookies, signed URLs and personal data.

# Supply Chain and Artifacts

Treat CI dependencies and artifacts as part of the production trust boundary. Pin third-party GitHub Actions to full-length commit SHAs for immutable use when risk warrants it, and verify the SHA belongs to the intended upstream repository. Keep workflow permissions least-privilege and avoid exposing secrets to untrusted code. Generate checksums/provenance metadata for release artifacts when useful; GitHub artifact attestations can establish cryptographically verifiable build provenance including repository, workflow, environment and commit context. Record SBOM/dependency information for products that need stronger supply-chain assurance. Preserve artifact identity through promotion so the build tested is the build released. A version tag alone is not provenance if the artifact cannot be traced back to source and workflow.

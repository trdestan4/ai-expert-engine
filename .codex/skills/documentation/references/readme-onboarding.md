# README and Onboarding

A repository README should answer what the system is, prerequisites, supported runtime/tool versions, how to install/bootstrap, required environment-variable names, how to run development/tests/build, and where deeper documentation lives. Keep secrets out of examples and provide `.env.example`-style placeholders when appropriate. New-contributor onboarding should explain repository layout, key conventions, common commands, test expectations and how to verify a change. Prefer commands copied from actual package scripts/configuration rather than invented generic instructions. Separate optional tooling from mandatory prerequisites. If setup differs by platform, document only supported paths or clearly label variants. Periodically execute or mechanically validate setup steps because stale bootstrap documentation can block contributors even when application code is healthy.

# Runbooks, Operations and Release Documentation

Operational docs should be executable under pressure. For each important incident/failure scenario include symptoms, scope, prerequisites, first dashboards/log queries/checks, safe mitigation options, actions that are dangerous or irreversible, rollback/restore/reconciliation steps, escalation ownership and post-action verification. Deployment documentation should explain environments, promotion, migration ordering, secrets/config ownership and rollback limits. Release/migration notes should state exactly what operators/users must do, compatibility windows and how success is verified. Maintenance docs should identify recurring jobs, backups, certificate/domain/provider dependencies and ownership. Avoid generic phrases like “check logs” without naming where and what to inspect. Exercise high-value runbooks periodically; documentation that has never been tested is operationally lower-confidence.

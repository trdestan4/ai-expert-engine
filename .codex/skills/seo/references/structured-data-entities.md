# Structured Data and Entity Signals

Structured data must describe visible, authoritative page/business/product facts. It is not a ranking hack and never justifies fabricated reviews, price or availability.

## Selection

Use schema types/properties supported by current search features and appropriate to page intent. Prefer a coherent graph with stable entity IDs/URLs for Organization/LocalBusiness/Product/Article/Breadcrumb/etc rather than unrelated duplicate blobs.

## Product

Price/currency/availability/review data must match the page and authoritative commerce state. Variant modeling should follow current search/schema support; do not mark a price range or rating that users cannot verify.

## Organization/local

Keep name/address/phone/URL/social profiles consistent with real organization listings. Location-specific pages need unique useful content/service context rather than doorway duplication.

## Validation

Validate JSON-LD syntax/schema and use search-engine rich-result tools where relevant. Monitor enhancement/report errors after deploy. A technically valid schema can still be semantically misleading.

## Entity/content coherence

Support entity understanding through clear authorship/about/contact, consistent naming, internal linking and evidence. Do not create dozens of schema properties that are absent or contradictory on page.

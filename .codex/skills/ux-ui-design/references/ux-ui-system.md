# UX/UI System Reference

## Sequence

1. primary user jobs;
2. information architecture;
3. task flows;
4. content/action hierarchy;
5. layout/grid/density;
6. components and states;
7. responsive re-composition;
8. creative styling;
9. implementation handoff.

## Layout rules

Use cards only when content genuinely benefits from grouping/independent surface behavior. Avoid universal rounded-card shells. Choose grids from content relationships. Define full-bleed moments intentionally.

## Responsive rules

For every major region decide: preserve, reflow, reorder, collapse, transform into a different component, use progressive disclosure, become sticky, or use alternate imagery. Mobile is not desktop stacked vertically.

## State completeness

Relevant components/flows should consider default, hover, focus, active, selected, disabled, loading, error, empty, success, destructive confirmation, and permission/availability states.

## Handoff

Specify component boundaries, tokens, content limits, states, interactions, accessibility expectations, responsive rules, and edge cases—not just visual measurements.

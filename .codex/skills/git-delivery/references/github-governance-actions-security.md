# GitHub Governance and Actions Security

Use repository rulesets/branch protection for critical refs: required reviews/checks, restricted force pushes/deletions and appropriate merge controls. CODEOWNERS should map meaningful ownership and be combined with protected review requirements when it matters. GitHub Actions workflows need least-privilege `permissions`, protected environments for sensitive deployments, and careful handling of fork/untrusted pull requests. Avoid interpolating untrusted input directly into shell commands. Pin third-party actions to full-length commit SHAs when immutable supply-chain control is required; verify pins originate from the intended upstream. Prefer OIDC federation to long-lived cloud credentials where supported. Keep workflow secrets environment-scoped and do not expose them to arbitrary PR code. Artifact attestations can strengthen provenance for distributed artifacts, but do not replace secure source/review/build practices.
